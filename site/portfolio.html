PC_HEALTH

FINISHED v0.1.0 IN DAILY USE MIT LICENSED
SCREENSHOT · PC_HEALTH SNAPSHOT / MCP OUTPUT

A longevity monitor for Windows PCs.

The job. Watch the health of a Windows PC over time — drive wear, temperatures, GPU, and system errors — and keep a timestamped record so you can see trouble coming before a drive dies on you. Read-only by design: there’s exactly one network call in the whole tool, to a sensor service on my own machine. Nothing leaves the box.

What’s mine. The layer on top of the sensors: polling four sources on a sensible schedule, deciding what counts as healthy versus worrying, writing clean timestamped JSON snapshots — and handing it all to an AI through an MCP server with five typed, read-only tools.

PC Control Hub

FINISHED · PAUSED v1.0 · 5 JUL JUN – OCT 2026 AUDITED BEFORE EVERY TAG
SCREENSHOT · HUB ON PHONE

Run my PC’s AI from my phone.

The job. Drive Claude Code on my PC from my phone, anywhere. The phone is a thin web screen; the PC does the work. One live connection with a heartbeat, so the phone shows grey or red within about five seconds if the link drops. The AI on the PC works with full access, the same way I run it at my desk, so all the protection sits at the door.

What’s mine. All of it: ~20,300 lines of Python core and a ~6,700-line phone interface. It has 1,104 commits. 245 are mine; the other 859 were made by AI agents working in roles I set up, and every one is stamped with the role that made it, so the history shows who did what.

Built to recover, with its own system. Before every deploy, the tool takes a backup of exactly the files it’s about to change. If the new version crashes three times in a row within seconds, the watchdog puts the saved copy back by itself, with no AI involved. If it’s down while I’m at the PC, one double-click restores it. Git sits underneath as the history: every change is a commit with the reason written down.

ETS2LA — campaign complete

Fixing a four-year-old self-driving mod from the ground up, and keeping it in Python.

ETS2LA is a self-driving mod for Euro Truck Simulator 2. The upstream team is rewriting it in C#, citing performance, maintainability, and code quality. I checked — fifty analysis passes through the codebase — and those reasons don’t hold up. The bugs people actually hit are discipline-and-pattern bugs that come back one-for-one in C# unless you fix the pattern first. This is my own campaign, not a pull-request job: the mod is theirs, GPL v3; the campaign and the argument are mine.

The maintainers won’t merge AI-written code, so the fixes stay in my copy. I finished the campaign anyway, as a learning job done properly from start to end.

“Write like you’re explaining the fix to a foreman, not pitching to a board.”
THE RULE THE REPORT OPENS WITH
BUG LEDGER · 9 CLOSED AND VERIFIED LAST CLOSED JUN 6
ETS-021/022
Arbitrary code execution through the settings fileThe loader ran pickle.loads(eval(value)) on text read straight out of SQLite. Replaced with json.loads; eval and pickle removed from that path. Verified with a hostile-input round-trip test and an in-game window-drag.
ETS-024
A second code-execution hole, in the model-file loadereval() on the contents of a model file. Swapped for ast.literal_eval. Supply-chain reachable — a poisoned model file would have run on the next update check.
ETS-023
Window position that never savedA function that recorded window position was never called. Dead since at least August 2025. Two-line fix, verified in-game.
ETS-005
Map page froze on the second openStale websocket subscription state that never reset on close. Three-line fix, verified in-game.
ETS-025
Silent failures given a voiceThree places in the settings code swallowed errors without a word. One logging import gave each of them a diagnostic line. Verified on the bench and in a two-hour live run.
ETS-026
A retry counter that never countedA database read retried itself with the same counter every time, so the retries were never bounded. Passed the next count instead of the same one. Verified before closing.
ETS-028
A typo’d setting failed silentlyReading a missing or misspelled setting quietly returned nothing, hiding the mistake. It now raises an error right where the typo is. Verified on the bench and in-game.
ETS-030
Lane-change check crashed on an empty routeThe manual lane-change check read the route plan without checking it had anything in it. Guarded against an empty plan; confirmed on a test drive.

How I ran it. Four roles: a Director (Talos) for strategy and scope, an Auto Drive Agent that proposes and lands fixes in the working copy under my checkpoints, an Auto Drive Strategist for a second opinion each cycle — and me as operator, routing between them and driving every fix in-game before it counts as done. Kanban board, append-only JSONL ledger, session logs, handovers.
